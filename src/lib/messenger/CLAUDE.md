# Messenger automations (the Page's chat answers by itself)


Settings → Messenger → **Automations** (`/[tenant]/admin/settings/messenger/automations`, `settings` permission, store-wide accounts only). Plan: `docs/plans/2026-11-10-messenger-automations.md` (release 1 = triggers, menu replies, editor; release 2 = chat cart + order updates).

- **Webhook** (`/api/webhook`): verify signature → 200 → work in `after()` (Meta wants 200 within 5 s and unsubscribes a Page after an hour of failures). Decisions live in `src/lib/messenger/handle-event.ts` (pure, deps injected); `webhook-deps.ts` holds the real side effects. Events are answered once (`dedupe.ts`, Redis SET NX, fails OPEN).
- **Rules** = trigger (keyword `contains`/`exact` on WHOLE words, Get Started, ice breaker ≤4, chat-menu button ≤5, fallback) + action (`menu_card`, `categories`, `category_items`, `featured_items`, `text`, `hours_location`, `talk_to_staff`, `order_status`, `cart`). One zod schema (`rules.ts`) validates on save AND on read. A store with `messenger_settings.rules_customized_at` NULL runs `DEFAULT_RULES` = the pre-2026-11-10 keywords + Filipino ones; after the first save its rows are the whole set (even empty). Saves go through `save_messenger_rules` (one transaction, `rules_version` CAS → 40001).
- **Replies** (`replies.ts`) clip to Meta's limits (`limits.ts`; `limits-contract.test.ts` walks every action over awkward menus). The editor preview renders the same `OutgoingMessage[]`. Postback/quick-reply payloads are `wn1|verb|…` (`payload.ts`), unsigned on purpose: every id is re-checked against the Page's store; foreign payloads (other bots) are ignored.
- **Staff takeover**: an echo whose `app_id` isn't ours (`FACEBOOK_APP_ID`) and lacks our `metadata: "wn"` = a person in Page Inbox → `messenger_sessions.bot_paused_until` (setting, default 60 min). While paused, typed messages get no bot answer; taps on our buttons still do. Staff `/menu`, `/categories`, `/hours` send that card without pausing. Typing "menu" in Inbox no longer sends a card (owner, 2026-11-10).
- **Links never carry a PSID**: `?m=<token>` (`link-token.ts`, 30 days, names a `messenger_sessions` row). The storefront keeps it opaque; `resolveMessengerRecipient` (`recipient.ts`) turns it into the PSID for THIS store only — `createOrderAction` and `send-cart` use it, so a browser can no longer put someone else's PSID on an order. Raw `?psid=` from old cards is accepted only with an existing session until 2026-11-24. `messenger_sender_id` / `messenger_last_interaction` are server-owned customer_data keys.
- **Messenger Profile** (`profile.ts` + `profile-sync.ts`): synced on save, skipped when the hash is unchanged (10 calls / 10 min per Page), and only fields WE set are ever deleted (`profile_fields`).
- **Tables** (`20261110120000`): `messenger_rules`, `messenger_settings` (tester PSID + profile state are service-role only), `messenger_sessions` + `(tenant_id, psid)` unique, `last_inbound_at` (24h window), `bot_paused_until`. APPLIED + probed on platform 2026-11-10 (as `20261110000421_messenger_automations`; real roles: owner saves, stale save 40001, staff without `settings` / branch-locked / other store / anon refused 42501, tester PSID + sessions unreadable to staff). Old `UNIQUE(psid)` drops in release 2. PGlite: `tests/sql/run-messenger-automations.cjs`.
- **Test send**: the owner messages their Page `TEST 123456` (code from the editor, 10 min, hash stored) → their PSID becomes `tester_psid`; "Send test" only works inside Meta's 24h window.
- Order updates outside 24h need utility templates (`page_utility_messaging`, not in the 2026-11-04 App Review) — POST_PURCHASE_UPDATE and the other tags are gone (2026).
- **Chat cart** (release 2, `chat-cart.ts` pure, `chat-cart-store.ts`): `messenger_sessions.cart_data` = `[{itemId, qty, name}]`, ≤20 lines × ≤50, simple dishes only (a required choice opens the item page). Prices are NEVER stored — every cart reply re-prices from the cached storefront menu and drops what can't be ordered (told by name); writes are compare-and-set on `cart_version` (two taps = two events side by side). A reply that shows the cart/orders declares `needs` in `decideReply`; `handleEvent` reads them before the pure builder runs. Checkout = `/cart?mc=1&m=<token>` → `MessengerCartImport` loads it via `POST /api/messenger/chat-cart` (token must be THIS store's; asks before replacing a non-empty web cart). `createOrderAction` empties the chat cart when the order came with a valid link (`verifyMessengerCustomerData`).
- **Where is my order** (`recent-orders.ts`): this PSID's orders at this store, last 7 days, newest 3, `orders_messenger_psid_idx` (partial, built CONCURRENTLY). Platform stores only (`StoreBundle.isPlatformOrders`); Convex / per-store-DB stores get the tracking-link text (D7).
- **Status messages** (`order-view.ts` `decideOrderUpdate`, `order-update.ts`): trigger `orders_messenger_order_update` (status change to confirmed/preparing/ready/delivered/cancelled on an order with `customer_data.messenger_psid`) pg_net-posts `{order_id}` to `/api/messenger/order-update` — unauthenticated like notify-order; everything re-read, `messenger_order_updates (order_id, status)` is the once-only claim + outcome (service role only). Sent as `messaging_type: UPDATE` only inside 24h of the customer's last message, bot on, not paused, status chosen in `messenger_settings.order_updates` (NULL = on for preparing/ready/delivered/cancelled; editor card "Order status messages"). Wording per status, `{store}`/`{order}`, always a Track order button. Migration `20261111090000` APPLIED + probed on platform 2026-11-10 (owner insert/update/read back 1 row, other store 0, anon + staff 42501 on claims and the trigger function, a real status change queues exactly one pg_net call, rolled back); `090100` index built CONCURRENTLY (valid). `090200` drops `UNIQUE(psid)` — apply only AFTER this code is live. PGlite: `tests/sql/run-messenger-chat-cart-order-updates.cjs`.
- **Messenger Studio** (2026-11-12, plan `docs/plans/2026-11-11-messenger-studio-and-chat-inbox.md`): the Automations page is a full-screen studio built from Branding Studio parts (`src/components/admin/messenger-studio/`: Journey · Auto-replies · Messages · Settings & test, phone canvas with Preview / Test chat). The Test chat runs the real `decideReply` + builders in the browser (`chat-simulator.ts`), so `decide.ts` must stay browser-safe (no crypto, no DB). Saving RULES syncs the Page's Messenger Profile: verification specs save words only.
- **Every bot message is one registry entry** (`messages/registry.ts`; ids are stored — never rename): replies call `say(ctx, id)`; the owner's words live in `messenger_settings.messages` (`20261111212438`, applied) with `lang` `en`|`tl` (Taglish is one tap; English default). `replies-golden.test.ts` pins un-customised output byte-for-byte.
- **"Only when" open / closed** on keyword, Get Started and fallback triggers (`trigger.when`; starter questions and chat-menu buttons always answer). Open = the store's OWN hours (`ReplyStore.isOpenNow`, independent of enforce-hours / pre-launch; no hours = open). A Get Started / fallback limited to the current state beats the always one; one of each per choice (`ruleSetProblems`).
- **Chat log** (`20261111224021_messenger_chat_log.sql`, APPLIED + probed 2026-11-12): `messenger_messages` = one short line per thing said (`chat-log.ts` pure: customer text / button title / "📷 Photo", bot replies as ONE summary line without links, staff echoes), `mid` unique (retries skipped), purged after 30 days by pg_cron `messenger-messages-purge`. `messenger_sessions` gains the customer's Messenger `first_name`/`last_name`/`profile_pic_url` (User Profile API, monthly; daily retry after a miss; failure = no name, never a failed reply) and `last_message_at`/`_preview`. Service-role writes only; reads = order readers (`app_user_may_read_messenger_chat` mirrors the orders SELECT policy: store-wide with an order key, branch accounts only chats with an order at their branch), sessions' `cart_data`/`checkout_state` stay service-only (column grant). App RPCs `messenger_chat_for_order(order_id)` / `messenger_chats(tenant, limit, before)` are SECURITY INVOKER. PGlite: `tests/sql/run-messenger-chat-log.cjs`. The merchant-app screens (B2) are designed, not built.
