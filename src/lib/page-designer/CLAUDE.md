## Page Designer (checkout, thank-you, tracking)

`/[tenant]/admin/page-designer/<tracking|thank-you|checkout>` (sidebar: Store Setup → "Page Designer", full-screen) is the SAME editor as the Hero/Welcome Builders with a `page` surface (`components/page-designer/editor/`). Plan: `docs/plans/2026-11-04-page-designer-checkout-thankyou-tracking.md`.

- **Page blocks**: ONE widget kind `page-block` (`content.block` = registry id) carries a page's working parts (payment picker, order status, place order). Registries `src/lib/page-designer/blocks-<page>.ts` (ids are stored in designs — never rename); text slots fall back owner → `storefront_labels` (`labelKey`) → built-in. The engine never imports page code: each page passes renderers through `PageRuntimeProvider` (`renderer/page-runtime.tsx`), live on the storefront, samples in the editor (`components/page-designer/samples/`).
- **Locks**: `required` blocks can't be removed or duplicated (`PAGE_NODE_POLICY`), publish refuses one missing/hidden/"Show when"-limited on any device (`pageDesignProblem`), and `preparePageDesign` appends any still missing at render, per device. Each block appears once. The checkout voucher field is required; the thank-you Messenger block is optional — without it a failed save tells the customer to contact the store (owner, 2026-11-05).
- **Show when** (`showWhen` on sections/widgets) + `{tokens}` (`PAGE_META[page].tokens`, plain string replace) — tracking states are order statuses, thank-you `success|failed`.
- **Stored** in `tenants.<page>_design` (TEXT v5 JSON, read via `resolvePageDesign`) + `<page>_design_enabled`; unpublished = today's page code path untouched. `confirmation_redirect` (`instant|countdown|stay`) + `_seconds` = what happens after the order saves (Messenger, kiosk and failed saves always stay). `20261104120000_page_designer.sql`; a change from a client role needs `store_setup` (or platform `stores.edit`): `tenants_guard_design_columns` (`20261109120000`, NOT yet applied) also covers `hero_design`/`hero_preset`/`hero_section_enabled` — a new builder column joins its list.
- Never offered: `embed` (any page), `html` on checkout, `order-entry`/`store-logo`.
- **Block designs + knobs** (2026-11-05, plan `docs/plans/2026-11-05-page-designer-block-designs-and-colours.md`): a block's design (`variant`, a gallery of LIVE thumbnails re-rendering the block's sample renderer), colours (`color_*`, '' = follow the page) and settings are ordinary block options (`src/lib/page-designer/knobs.ts`), stored in the design — no column. The FIRST design and every default reproduce the block's pre-knob look exactly (snapshots pin it); never rename a choice value. `showWhen` hides settings that don't apply to the chosen design. Checkout + thank-you colours: `withCheckoutColors` hands the block a store row with the knob in place of the `checkout_*` column (derived shades follow); tracking: `tracking-colors.ts` over `tracking_style`. Image knobs are https only (`safeMediaUrl`, ≤600 chars). Order type has 7 designs (`order-type-choices.tsx`; `tiles` = the shared `OrderTypeSelector`).
- **Look tab** (left rail, replaces "Theme" on page surfaces): the page's Branding Studio settings (`PAGE_LOOK_SECTIONS` in `look.ts`, built from the Studio registry — checkout/thank-you: `checkout_*` colours; tracking + checkout: Order status / Loyalty card `tracking_style`; each page's `storefront_labels`). SAME columns as the Studio (one source of truth, so a change also shows on the standard page). Edits preview live (the editor recomputes the canvas vars and `PageRuntime.store`) and save with Publish or "Save look now" through `saveBrandingWithClient` — only the page's own fields, JSON columns folded over the CURRENT row, refused when a field moved since the editor opened (Studio saved meanwhile). Publish checks the design BEFORE writing any colour. It also offers whole-store settings (status colours, main button, fonts — labelled "also changes your menu") and clears a Studio PHONE override of a field (`mobile_overrides.<field>` ids, clear-only) so a phone colour never silently beats the edit.
- **Part styles** (v3, 2026-11-05, plan `docs/plans/2026-11-05-page-designer-v3-style-templates-forms.md`): components mark parts with `data-part` (+ `data-on` chosen / `data-done`); `src/lib/page-designer/parts.ts` is the ONE registry (part ids + props, stored as `p_<part>_<prop>` — never rename). Block level = the block's `content.options` (Style tab: design gallery, quick styles, block colours, every part, copy/paste/use-on-every-block); page level = `design.page.parts` (Look tab › Page style); block wins by specificity. `buildPartCss` (from css.ts) emits validated, scoped `!important` rules; nothing set = no rule, so unstyled pages are unchanged (snapshot-diff proof: only part attributes added). A block offers only the parts in its registry `parts` list (+ card/title/subtitle/text/muted); publish refuses others. New element in a block = mark it + list it (the `*-parts.test.tsx` suites fail otherwise).
- **Layouts**: `design.page.layout` = `steps` (each section a step, Next asks `PageRuntime.stepProblem` — checkout: `checkout-step-problem.ts`, mirrors handleProceedToPayment) or `accordion`; `section.pin = 'bottom'` = sticky bar shown on every step. Every section stays mounted (hidden), so typed answers survive. Editor shows all sections with step badges. `page` + `pin` are in the zod schema and `load.ts` (zod strips unknown keys — anything new on the design must be added to BOTH).
- **Blocks with nothing to show** take no room on the storefront: `:empty` rules in `css.ts` (+ the spacer after them), and `useEmptySections` (`page-layout.tsx`) drops a section whose blocks all rendered null from the scrolling page, the steps and the panels. It reads the DOM because only the blocks know, and some find out late. The Schedule block's Content panel (`schedule-orders-panel.tsx`) switches pre-orders per web order type, live: it shows only where `advance_order_enabled` is on and the server refuses a time anywhere else.
- **Removable blocks**: only Place order (checkout) and the status blocks (thank-you, tracking) are `required`. Others carry `neededWhen` (`order_choice`, `scheduling`, `questions`, `payment`, `gov_claims`, `kiosk`): the owner may remove/hide them and `preparePageDesign(design, page, needs)` adds a plain copy back in the browser while the live store needs it (`checkoutNeeds`; thank-you `kiosk`). Without a summary the place-order button always shows the total. The voucher block is removable (owner, 2026-11-05, reversing the earlier lock).
- **Templates** (`templates*.ts`, built with `template-kit.ts` `block()`, which validates every option/text/part and throws): 21 checkout incl. re-creations of the Studio layouts, plus families (`family` id, `templates-looks.ts`) on all three pages — picking one stores `pd-family:<tenantId>` and the other pages offer the matching look once (`family-banner.tsx`). Templates set shape/type only; the only fixed colours are the neutrals the template test allows.
- **Copy text** (`copy-text` widget, 2026-11-06, Page Designer only, tile added in `page-surfaces.ts`): words a customer copies with one tap (`src/lib/clipboard.ts` falls back to a selection copy; both blocked = select + "press and hold", because in-app browsers can refuse). Blank after tokens = nothing shown.
- **Show for** (`showFor` on sections/widgets, beside `showWhen`, in BOTH zod and `load.ts`): dine-in / pickup / delivery, from `PageRuntime.orderKind` (`order_types.type`, never the renameable label). No kind yet = shown; Grab, foodpanda and `other` follow Pickup (`isPickupLike`). Limits a required block = publish refuses. `{store_address}` = the order's branch, else the store (`store-address.ts`; tracking reads the branch once per page load, only when the design prints it, `order-store-address.ts`).
- **Form designs** (`checkout.customer`): `clean`, `label_inside`, `sheet`, `ruled`, `tinted`, `roomy` draw lines from the TEXT colour, never `--co-border`, so a strong store border can't paint every box. With a `look` the form lays out by its own width (`@container`, `@lg:`), so the editor's phone frame matches a real phone; the standard checkout keeps viewport breakpoints. Knobs: `address_map` (`buttons` | `links` | `map` | `hidden`; `resolveAddressMap` keeps the map for Lalamove / per-km stores, whose delivery is blocked without a pin; `map` is a preview that opens the picker on tap so a thumb can't get stuck scrolling; Apple Maps only, a Mapbox deployment keeps its buttons), `address_details` (`tucked` never hides an answer), `field_marks`. Templates: `templates-checkout-forms.ts`; every checkout template starts from `TIDY_FORM`.
- **Checkout questions in the Page Designer** (Content tab of `checkout.customer`, via `PageRuntime.blockPanels`): per order type, presets, checks in `validation_rules` (`checkout-field-rules.ts`: known keys only, fixed patterns only — never an owner regex), saved with Publish or "Save form now" by `saveCheckoutFormAction` (`form-save.ts`: store_setup, tenant-owned order types, CAS against the loaded questions, ops worked out server-side, result re-read). A part-way failure returns what IS stored (`isPartial`) so a retry never creates a question twice. Same rows as Order types and the POS. Types `choice` / `checkbox` (ticked = 'yes') / `date` — CHECK widened by `20261105130000` (APPLIED + probed 2026-11-05). Mistakes show beside the field (`aria-invalid`) as well as in the toast.
